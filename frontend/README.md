# Frontend README for KathaVaani

## Overview
This directory contains the **plain HTML/CSS/JS** frontend for the KathaVaani application. It provides six functional screens:
1. **Shop Front** – landing page.
2. **Counter (Upload)** – upload a PDF/TXT manuscript.
3. **Reading Nook** – page slider (max 5 pages) and language picker.
4. **Narrator Choice** – select male or female narrator.
5. **Binding** – progress bar while audio is being generated.
6. **Library** – audio player with text and download link.

All screens are wired to the existing FastAPI backend (running on `http://127.0.0.1:8000`). No additional styling beyond functional layout is included.

## Prerequisites
- **Backend** must be running. Follow the backend README to start the FastAPI server (`python run.py`).
- **Python 3.9+** with dependencies installed (`pip install -r ../backend/requirements.txt`).
- **Node.js / npm** are **not** required – the frontend is pure static assets.

## Workflow
1. **Upload** a manuscript (PDF or TXT). The file is sent to the backend `/api/extract` endpoint, which returns a per‑page text array.
2. **Select Pages** – use the slider to pick up to 5 pages (the UI enforces the limit).
3. **Choose Language** – the language picker is populated from the backend `GET /api/voices` response.
4. **Select Narrator** – two cards (male / female) are shown. Unavailable language‑narrator combos are disabled with a short note.
5. **Hear a Sample** – click *Hear a sample* on a narrator card to play a short preview (cached on the server).
6. **Bind** – press *Bind* to invoke `/api/synthesize`. A progress bar shows the synthesis status.
7. **Library** – after synthesis completes, the generated MP3 appears in the Library screen together with the text and a *Download* button.

## Development Tips
- **Hot‑Reload**: Since the frontend consists of static files, simply refresh the browser after editing `index.html`, `app.js`, or `style.css`.
- **Debugging**: Open the browser developer console (F12). Network requests to the backend appear under the *Network* tab – useful for verifying payloads and responses.
- **Cache**: Audio chunks are cached on the backend (`backend/cache`). When testing preview or synthesis repeatedly, you’ll see cache hits (no additional credits).

## Known Limitations
- No responsive/mobile styling – the layout is optimized for desktop browsers.
- No authentication – the frontend assumes the backend is accessible locally.
- The backend host/port is hard‑coded in `app.js`. Change the `BASE_URL` constant if you run the server elsewhere.
